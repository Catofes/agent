# 投屏链路验证记录

## 2026-08-19 自动化回归

验证环境：Linux amd64、Go 1.26.5、Node.js 内置测试运行器，代码基线 `091e98f`。本次不使用真实 DeepSeek API。

执行：

```bash
make test
```

结果：Go 全部测试和 `web/*.test.js` 全部通过。自动化逐段覆盖：

1. `POST /api/teacher/spotlight` 校验目标学生和完整回合，生成唯一 `spotlight_id`。
2. 服务端先保存权威快照，再通过 `screenHub` 广播；大屏后连接时仍可获取最新快照。
3. `GET /api/screen/events` 收到与本次投屏一致的 `spotlight_id`、单调 `revision`、学生设计和指定回合消息；前端忽略重复或乱序的旧版本。
4. 大屏页面真实渲染脚本在模拟 SSE 事件下更新姓名、Soul、Skill、装备和对话 DOM。
5. DOM 更新后，大屏调用 `POST /api/screen/ack` 回传同一 `spotlight_id`。
6. 服务端收到回执时，教师请求返回 `200` 和 `delivered:true`；过期回执返回 `409 STALE_SCREEN_ACK`。
7. 大屏未连接时，教师请求返回 `202` 和 `delivered:false`，不再误报“已推送到大屏”；快照仍被保存，大屏稍后连接可自动显示。

### 可观测性

- 教师状态墙显示“大屏已连接/未连接”及连接数。
- 大屏右上角显示 SSE 连接、重连或渲染失败状态。
- 大屏控制台记录 `SSE connected`、`event received`、`render failed` 和回执失败。
- 服务端日志记录大屏连接/断开、发布时的连接数、`spotlight_id` 以及回执或超时。
