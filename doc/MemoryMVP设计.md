# Memory MVP 设计与验收

## 产品语义

Memory 与对话历史是两套数据：

- 对话历史属于一个 `conversation_id`。新建对话后，模型请求不携带其他对话的消息。
- 长期 Memory 默认关闭。开启后，系统在主回答完成后异步提取候选；候选必须由学生确认，才可能进入后续模型请求。
- 已确认 Memory 仅在当前输入与条目相关时读取。读取不等于不可更改的事实，学生可以纠正、删除或清空。
- MVP 的 Memory 作用域是 `run_id + student_id`，只跨同一课堂场次内的对话。教师新建场次时不复制开关、候选或已确认条目。

## 生命周期

1. 学生显式开启 Memory。
2. 每轮主回答保存并向学生发送 `turn_end` 后，独立的提取任务最多提出 3 条候选。提取超时、格式错误、模型错误或存储错误均静默降级，不改变主回答结果。
3. 候选以 `candidate` 状态展示，不会注入模型。学生可编辑后确认，也可直接删除。
4. `confirmed` 条目才参与相关性筛选。新对话没有旧对话历史，但可读取筛选后的已确认 Memory。
5. 关闭开关会停止提取和读取，但保留条目；删除立即移除单条；清空物理删除该学生在当前场次的全部候选和已确认条目。

候选提取只允许稳定的偏好、背景、长期目标、称呼或持续学习需求；明确排除临时任务、模型推测、答案内容、指令、密码、密钥、联系方式和身份证件等高敏感信息。即使提取器输出不合适内容，候选仍须学生确认。

## 上下文回执

每轮用户消息持久化一份公开的上下文回执，学生实时发送或刷新历史时均可看到：

- Soul 是否已应用；
- 当前 Skill 是否已提供给模型，并明确“由模型按适用条件判断”，不声称能从隐藏推理证明采用；
- 本轮实际读取的 Memory ID 和正文，或“本轮未读取”。

回执描述平台实际组装的输入，不展示模型思考草稿、系统提示全文或隐藏推理。

## 数据和接口

- `memory_settings(run_id, student_id, enabled, updated_at)`：开关按学生、场次隔离。
- `memories(run_id, student_id, id, content, status, source_conversation_id, source_turn_id, created_at, updated_at)`：候选和确认条目。
- `messages.context_receipt`：本轮上下文回执，不重新发送给模型。
- `GET /api/memory`：查看开关、条目、用量、限额和作用域。
- `PUT /api/memory/settings`：开关。
- `PATCH /api/memory/{id}`：编辑或确认。
- `DELETE /api/memory/{id}`：删除单条。
- `DELETE /api/memory`：清空当前学生、当前场次的全部 Memory。

所有查询和变更均从登录 session 取得 `run_id + student_id`，请求参数不能指定其他学生或场次。

## 限额

默认值可通过启动参数或同名环境变量调整：

- 总条数：30（候选和已确认合计）；
- 单条长度：400 个 Unicode 字符；
- 总 prompt 预算：估算 1200 tokens，采用 UTF-8 字节数除以 3 的保守、与模型 tokenizer 无关的算法；
- 异步提取超时：20 秒。

相关环境变量为 `MAX_MEMORY_ITEMS`、`MAX_MEMORY_CHARS`、`MAX_MEMORY_TOKENS` 和 `MEMORY_EXTRACT_TIMEOUT`。

## 验收清单

- Memory 关闭时不提取、不读取；关闭后保留现有条目。
- 候选不会进入模型；编辑并确认后，在另一新对话的相关任务中可读取。
- 无关的已确认 Memory 不读取；每轮回执与实际注入条目一致。
- 学生 A 不能查看、编辑或删除学生 B 的 Memory；旧场次 Memory 不进入新场次。
- 超长单条或超过总 token 预算的编辑被拒绝；自动提取达到条数或预算后停止新增。
- 删除后查询不再返回，后续模型请求和回执均不再出现；清空后条目为零。
- 提取失败或超时不改变已完成的主回答，也不会向对话流发送失败事件。
