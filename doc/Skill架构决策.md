# Skill 架构决策

状态：v0.1 已确认，后续版本按本决策演进。

## v0.1：保留一份可选 Skill

v0.1 继续让每名学生编辑一份 `SKILL.md`，以降低公开课中的理解和操作成本。Skill 表示“当前任务适用时采用的方法”，不是固定角色、长期记忆或每轮必须执行的剧本。

- Skill 为空时，Agent 仍按 Soul 和通用能力正常回答。
- Skill 非空时，模型必须先判断当前任务是否匹配；不匹配时不套用。
- 装备工具只表示工具可用，不表示本轮必须调用。
- 当前把单份 Skill 放入 system prompt 是 v0.1 的兼容实现，不是最终的数据模型或选择机制。

## 后续：支持多 Skill，但不纳入 v0.1

多 Skill 计划在 v0.1 稳定后实现。每项至少包含：

- 稳定 ID、名称；
- 学生可理解的说明和触发条件；
- Markdown 正文；
- 启用状态、更新时间。

模型请求应先根据“名称 + 说明/触发条件”选择与当前任务相关的 Skill，再提供被选中的正文；不应无条件注入全部正文。学生端需要显示本轮实际采用的 Skill，但不得展示隐藏推理。

现有 `designs.skill_md` 迁移时转换为一项默认启用的“我的 Skill”，不丢失学生内容。多 Skill 仍按 `run_id + student_id` 隔离，除非后续产品决策明确允许跨场次复制。

## 与其他概念的边界

- Soul：身份、价值取向和表达风格。
- Memory：经过确认、可纠正和删除的事实。
- Skill：任务匹配时采用的方法。
- Tool：由平台执行的受控外部能力。

优先级保持为：平台安全规则 > Soul > 当前任务相关 Skill > 可用 Memory > 当前对话。
